# Youni4st Mini App — Telegram-вход и профиль

Подготовлено для **@youni4st_bot**, 30 октября 2026 года.

## Что изменено

- Одна кнопка «Войти через Telegram». Экран входа по e-mail удалён; телефон не используется для авторизации.
- Вход подтверждается сервером: проверяются подпись `initData` и срок её действия. Значения `initDataUnsafe` и флаг в памяти браузера не дают доступ к аккаунту.
- Профиль привязан к постоянному Telegram ID. При входе обновляются имя, username и доступное фото. Username не придумывается, если он не задан в Telegram.
- В синем баннере: аватар слева; справа имя, @username и выбранный статус. Статусы: «Абитуриент», «Студент», «Выпускник», с RU/KZ/EN переводами. До выбора статус в баннере отсутствует.
- В редакторе имя и username доступны для просмотра; менять их нужно в Telegram. Статус обязателен при сохранении; контактные телефон и e-mail необязательны.
- Статус и данные профиля сохраняются на сервере, доступны с другого устройства после Telegram-входа. Локальные данные разных Telegram-аккаунтов разделены.
- Выход с подтверждением, отзыв серверной сессии и возвращение к входу.
- Чат использует совместимый с Android Gemini-адаптер. Исправлен формат истории: максимум 10 предыдущих сообщений, без повторения текущего вопроса и лишнего поля `lang`.
- Компактный логотип на входе взят из предоставленных Android-исходников 0.8.2.

Это **этап авторизации и профиля на основе предоставленной Flutter Mini App**. Остальные экраны и каталоги сохраняют основу этой Mini App. Этот архив не следует считать полным переносом всех экранов, каталога вузов и PDF-резюме из Android 0.8.2. Исходная папка `youni4st #2` и Android ZIP не изменялись.

## Можно ли оставить ключи ИИ

**Да.** Существующие `GEMINI_API_KEY`, `GEMINI_MODEL` и `CHAT_ENABLED` остаются серверными настройками. Для Telegram не требуется отдельный ключ Gemini. Android и Mini App будут расходовать общие квоты Google-проекта. Новый ключ в том же Google-проекте не создаёт отдельную квоту.

`TELEGRAM_BOT_TOKEN` — отдельный токен бота **@youni4st_bot**, необходимый для проверки Telegram-входа. Его добавляют только в Environment сервера, не во Flutter, не в GitHub и не в переписку.

## Запуск на Render

Вместе с исходниками подготовлен отдельный архив **Youni4st-miniapp-telegram-deploy.zip**. Он содержит готовую папку `web_dist` и Python-сервер; Flutter на Render устанавливать не нужно.

1. Распаковать deploy-архив и разместить его **содержимое** в репозитории: в корне должны находиться `server/` и `web_dist/`.
2. Подключить репозиторий к Python Web Service. Build Command: `pip install -r server/requirements.txt`.
3. Start Command: `uvicorn main:app --app-dir server --host 0.0.0.0 --port $PORT --workers 1 --no-access-log`.
4. В Environment добавить настройки из `server/.env.example`, включая `TELEGRAM_BOT_TOKEN` и существующие значения Gemini. Не загружать настоящий `.env` в GitHub.
5. Для постоянных профилей подключить PostgreSQL и задать `DATABASE_URL`. Альтернатива — постоянный диск и `SQLITE_PATH`, указывающий на этот диск. Обычная файловая система Render не подходит: данные пропадут при пересборке/перезапуске. На Render сервер намеренно не запускается без явно указанной базы/пути постоянного хранения.
6. После успешного запуска проверить `/health`. Этот маршрут проверяет состояние ИИ; настоящий Telegram-вход проверяется отдельно через бота.
7. Открыть сайт сервиса. В обычном браузере кнопка ведёт к **@youni4st_bot**; сервер не делает фиктивный вход без Telegram.
8. В BotFather настроить **Main Mini App** или кнопку меню для **@youni4st_bot**, указав HTTPS-адрес сайта сервиса. Запускать через кнопку приложения/меню или `https://t.me/youni4st_bot?startapp`, а не обычную ссылку в сообщении: необходимы подписанные данные пользователя.
9. Открыть Mini App в Telegram, войти, проверить имя/username, выбрать статус и повторить вход на другом устройстве.

Если новый код устанавливается на существующий AI-сервис, сначала настроить базу и сохранить его текущие переменные Gemini. `/api/chat` и `/health` остаются совместимыми с Android. Если выбран новый сервис, текущий Android-сервер можно оставить без изменений и задать на новом сервисе те же Gemini-настройки. Автоматической публикации из этого чата не было.

### Если интерфейс и API на разных доменах

По умолчанию интерфейс обращается к API на своём домене. Для раздельного размещения пересобрать Flutter с `--dart-define=MINIAPP_API_URL=https://АДРЕС-СЕРВЕРА`, а в `ALLOWED_ORIGINS` сервера указать точный origin интерфейса без завершающего `/`. Не использовать `*`.

## Локальная разработка

Использован Flutter **3.41.6**, Dart **3.11.4**, Python **3.12**.

```text
flutter pub get
flutter test
flutter build web --release --no-web-resources-cdn --no-wasm-dry-run
```

Содержимое `build/web` скопировать в `web_dist` рядом с `server`. Для сервера:

```text
pip install -r server/requirements.txt
cd server
python -m unittest -v test_telegram
uvicorn main:app --host 127.0.0.1 --port 8080 --no-access-log
```

На локальном компьютере без `DATABASE_URL` используется SQLite `data/miniapp.sqlite3`. Это режим разработки, не инструкция хранить производственные профили на временном диске. Тестовые подписи и вымышленные аккаунты находятся только в тестах; клиентская сборка их не содержит.

## Что нужно учитывать перед общей публикацией

- Живой вход с настоящим токеном бота ещё не проверен: токен не предоставлялся и настройки BotFather/Render не менялись. Проверены серверные подписи и полный локальный браузерный сценарий с вымышленным аккаунтом.
- PostgreSQL-подключение предусмотрено; проверки хранения выполнены на SQLite. На выбранной производственной базе нужен контроль входа и повторного открытия профиля.
- Telegram-аккаунты не связываются автоматически с аккаунтами Firebase Android: для этого позднее нужен отдельный подтверждённый сценарий привязки.
- Старый клиентский Bitrix webhook убран из публичного кода. Для существующих заявок/консультаций предусмотрен серверный `BITRIX_WEBHOOK_URL`; без него CRM-заявки не отправляются. Автоматические сообщения о статусе должны исходить из доверенного CRM webhook, а не из произвольного запроса браузера. На этом этапе исходящие уведомления отключены.
- Старый мобильный PDF-экспорт и остальные интеграции Mini App требуют отдельной проверки при полном переносе 0.8.2. В частности, старый код загрузки PDF содержит неверно экранированный URL; его перенос не входит в этот этап.
- Старый отдельный сервер `server/main.py` из предоставленной папки содержал встроенный ключ b.ai; в этот архив он не переносился. Если тот ключ или старый CRM webhook уже публиковались, их следует перевыпустить в соответствующих сервисах.
